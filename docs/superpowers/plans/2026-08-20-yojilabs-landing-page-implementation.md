# YojiLabs Landing Page Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a localhost-first, frontend-heavy YojiLabs marketing site with a polished homepage, mocked booking/intake/contact flows, and clean seams for future backend and real-site integration.

**Architecture:** Use a server-first Next.js App Router application with local content/config data, route-based conversion flows, and replaceable mock adapters for booking and submission handling. Keep the homepage visually rich but structurally simple, and isolate mutable content, external URLs, and mock state away from presentation components.

**Tech Stack:** Next.js App Router, TypeScript, Tailwind CSS, React Server Components, minimal client components, local SVG/raster assets, Playwright for route smoke coverage, Vitest/RTL only if needed for isolated client logic.

## Execution Notes

- Keep the build localhost-first until the site feels complete.
- Do not wire real backend persistence in v1.
- Do not link directly to the live Pantry route from localhost unless explicitly requested during implementation.
- Only update the spec if implementation reveals a true contradiction, not just a preference shift.
- Preserve `YojiLabs/` reference assets untouched.

## Completion Criteria

The implementation is ready to hand off when:

- all planned routes render locally
- homepage structure matches the approved spec
- all form and booking flows work end-to-end in mocked localhost mode
- internal CTA routing matches the spec exactly
- non-production noindex behavior is in place
- build and smoke tests pass
